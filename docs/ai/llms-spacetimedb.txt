# SpacetimeDB Integration Guide

## Philosophy
SpacetimeDB combines database, application logic, and serverless execution into a single unified in-memory engine.
Clients communicate over WebSocket, syncing subscribed tables directly into local in-memory memory caches.

## MCP Server
- Command: `spacetime mcp`
- Reads schema, tables, and reducers directly from local server or SpacetimeDB Cloud.

## Schema as Single Source of Truth (SSOT)
- NEVER declare arbitrary ad-hoc `interface DbRecord` or loose types in client code.
- Tables, rows, and reducer payloads must strictly derive from `src/schema/spacetimedb.ts` or generated `src/module_bindings/`.

## TypeScript Client Workflow
1. Generate module bindings:
   ```bash
   spacetime generate --lang typescript --out-dir src/module_bindings
   ```
2. Build connection & register subscriptions:
   ```typescript
   import { DbConnection, tables } from '~/module_bindings'

   export const conn = DbConnection.builder()
     .withUri('ws://localhost:3000')
     .withDatabaseName('my_app')
     .withAutomaticReconnect()
     .onConnect((connection) => {
       connection.subscriptionBuilder()
         .onApplied((ctx) => {
           console.log('Cache populated:', ctx.db.my_table.count())
         })
         .subscribe([tables.my_table])
     })
     .build()
   ```
3. Reactive updates with Solid.js:
   - Call table row event hooks (`conn.db.my_table.onInsert`, `onUpdate`, `onDelete`) to update Solid signals/stores.
4. Calling reducers (transactions):
   - Reducers are invoked like direct typed functions: `conn.reducers.createItem({ title: 'New Item' })`.
